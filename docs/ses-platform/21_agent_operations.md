# 에이전트가 부르는 연산

작성일: 2026-11-23. 구현은 `ses_core/ops.py`, 명령은 `ses ops`와 `ses call`, 시험은 `tests/test_ops.py`다. 묶음의 계약은 `20_packs.md`에 있다.

## 0. 무엇을 정했나

연구실의 구도는 분야의 표현을 SES로, 실행을 DEVS로 두고 그 둘을 에이전트가 엮는 것이다. 이 문서는 에이전트와 플랫폼 사이의 경계를 정한다.

- 에이전트가 하는 일. 묶음의 파일을 글로 고친다. 문서, 모델 베이스, 바인딩, 사례의 결정이다.
- 플랫폼이 하는 일. 고친 묶음을 판정한다. 무엇이 어디서 틀렸는지를 부호와 함께 돌려준다.

플랫폼은 에이전트를 갖지 않는다. 언어 모델을 부르는 코드가 플랫폼에 없다. 어떤 에이전트든 여섯 연산을 부르면 된다. 연산은 사람이 쓰는 명령 `ses pack`과 같은 계산을 하고, 결과를 글이 아니라 JSON 값으로 낸다.

파일을 고치는 연산은 두지 않았다. 까닭은 셋이다. 에이전트는 이미 파일을 고치는 도구를 가지고 있다. 문서를 자료구조로 읽어 다시 적으면 주석이 사라진다. 그리고 연구자마다 다른 것은 내용이고 같이 쓰는 것은 판정이다. 편집 모델(13 문서)의 원시 연산을 연산으로 내놓는 일은 남겨 두었다.

이 문서가 주장하지 않는 것. 에이전트가 SES와 그 검사 덕분에 일을 더 잘한다는 것은 여기서 보이지 않았다. 여기서 만든 것은 그 평가가 올라설 표면이다. 평가의 틀은 아직 없다(7절의 R1).

## 1. 약속

1. 입력과 결과는 JSON 값이다.
2. 결과는 늘 같은 모양의 봉투다(2절). 연산이 실패해도 봉투가 온다.
3. 연산은 예외를 내지 않는다. 잘못은 봉투의 `findings`에 줄로 적힌다. 줄은 `severity`, `code`, `where`, `message`를 가진다.
4. `ok`는 `findings`에 `error`가 없다는 뜻이다. 그것뿐이다.
5. 연산은 작업 자리(root) 안의 디렉터리만 다룬다. 밖을 가리키는 경로와 밖으로 나가는 링크는 거부한다.
6. 파일을 쓰는 연산은 둘이다. `pack_new`와, `record`를 켠 `pack_check`다. 나머지는 묶음의 디렉터리에 아무것도 남기지 않는다. 바이트코드 파일도 남기지 않는다.
7. 결과의 크기에는 한도가 있다. 잘린 곳에는 잘렸다는 표시가 있고, 수는 전체의 것이다.
8. 묶음의 코드가 표준 출력에 찍는 것은 봉투의 `output`에 든다. 결과에 섞이지 않는다.

약속하지 않는 것이 하나 있다. 묶음의 모델 베이스는 파이썬 코드이고, 검사와 실행은 그 코드를 연산을 부른 프로세스 안에서 돌린다. 연산은 그 코드를 가두지 않는다. 5번의 약속은 연산이 받는 경로에 대한 것이고 묶음의 코드가 하는 일에 대한 것이 아니다. 에이전트가 쓴 코드를 돌릴 때의 격리(컨테이너, 권한이 낮은 사용자, 시간 제한)는 부르는 쪽이 한다.

## 2. 봉투

```json
{
  "op": "pack_build",
  "version": "1.0",
  "ok": false,
  "findings": [
    {"severity": "error", "code": "P4", "where": "lab.ses.yaml",
     "message": "결정이 모자라다. Line/Worker: specialization speed 의 대안이(가) 정해지지 않았다. 남은 선택지: ['Fast', 'Slow']"}
  ],
  "result": null,
  "output": ""
}
```

| 항목 | 뜻 |
|---|---|
| `op` | 부른 연산의 이름 |
| `version` | 이 계약의 판. 지금은 1.0 |
| `ok` | `findings`에 `error`가 없으면 참 |
| `findings` | 줄들. `severity`는 error, warning, info 가운데 하나. `code`는 4절의 부호. `where`는 파일, 모듈, 사례의 이름 |
| `result` | 연산마다 다른 값(3절). 구하지 못했으면 null |
| `output` | 묶음의 코드가 표준 출력에 찍은 글. 4,000자를 넘으면 끝쪽만 싣고 앞에 잘렸다고 적는다 |

수를 싣는 법. 변이의 수처럼 클 수 있는 수는 `{"value": 9000, "text": "9000"}`의 모양이다. `text`는 늘 있고, `value`는 2의 53제곱보다 작을 때만 수이고 그 밖에는 null이다. 유한하지 않은 수는 글 "INF", "-INF", "NaN"이 된다. 모델이 낸 값 가운데 JSON으로 옮길 수 없는 객체는 글이 된다.

## 3. 연산

| 연산 | 언제 부르는가 | 입력 | 쓰는가 |
|---|---|---|---|
| `pack_new` | 새 분야를 시작할 때 한 번. 돌아가는 가장 작은 묶음을 만들고 바로 검사한다 | `dir`, 선택 `name` | 쓴다 |
| `pack_check` | 묶음의 파일을 고칠 때마다. 계약을 지키는지 본다 | `dir`, 선택 `record`, `executors` | `record`가 참일 때만 |
| `pack_show` | 묶음을 처음 볼 때. 선언, 사례와 적어 둔 기록, 파일의 목록 | `dir` | 안 쓴다 |
| `pack_choices` | 무엇을 고를 수 있는지 볼 때. 결정을 따르는 변이의 수와 선택 지점마다 남은 선택지 | `dir`, 선택 `case` 또는 `decisions` | 안 쓴다 |
| `pack_build` | 사례가 뜻한 구조인지, 속성의 값이 뜻한 대로인지 볼 때. 변이 하나의 구조와 속성의 값 | `dir`, 선택 `case` 또는 `decisions`, `defaults`, `depth`, `limit` | 안 쓴다 |
| `pack_run` | 모델의 행동을 볼 때. 사례 하나를 참조 시뮬레이터로 돌린 출력 사건 | `dir`, `case`, 선택 `until`, `offset`, `limit` | 안 쓴다 |

입력의 정확한 모양은 `ses ops`가 낸다. 연산마다 입력의 JSON Schema가 있고, 스키마에 없는 항목은 거부한다.

결과에 드는 것.

| 연산 | `result` |
|---|---|
| `pack_new` | `files`(만든 파일들)와 `pack_check`의 결과 |
| `pack_check` | `name`, `family`(변이의 수 `variants`와 적격인 변이의 수 `wellformed`), `cases`(사례마다 `built`, `variables`, `components`. 돌린 사례는 `atoms`, `links`, `events`, `last`, `digest`, `executors`. 돌리지 않는 사례는 구조의 지문 `structure`), `errors`, `warnings` |
| `pack_show` | `name`, `title`, `document`, `profile`, `model_base`, `binding`, `executors`, `cases`(사례마다 `name`, `decisions`, `defaults`, `until`, `recorded`), `experiments`, `files`, `files_truncated` |
| `pack_choices` | `variants`, `wellformed`, `points`(선택 지점마다 `owner`, `kind`, `group`, `state`, `remaining`, `options`). `state`는 open, decided, none_left 가운데 하나 |
| `pack_build` | `variables`, `components`, `nodes`, `structure`(구조의 지문), `tree`(구성요소마다 `name`, `labels`, `attributes`, `absent`, `parts`, 잘렸으면 `parts_not_listed`), `truncated` |
| `pack_run` | `variables`, `atoms`, `until`, `events`, `last`, `digest`, `offset`, `log`(사건마다 `t`, `at`, `port`, `value`), `truncated` |

`pack_check`의 `executors`는 실행기마다 reference, same, different, skipped, skipped_native, violates_convention, stopped 가운데 하나다. skipped는 그 실행기가 이 컴퓨터에 없다는 뜻이고 오류가 아니다.

한도.

| 무엇 | 기본 | 최대 |
|---|---|---|
| `pack_build`가 내는 구성요소의 수(`limit`) | 200 | 2,000 |
| `pack_run`이 한 번에 내는 사건의 수(`limit`) | 50 | 1,000 |
| `pack_show`가 늘어놓는 파일의 수 | 200 | 200 |
| `pack_choices`가 돌아보는 변수 값의 조합 | 200,000 | 200,000 |
| `output`의 글자 수 | 4,000 | 4,000 |

`pack_run`의 사건은 `offset`과 `limit`으로 나눠 읽는다. 나눠 읽은 것을 이으면 전체다. `digest`는 기록 전체의 지문이고 `pack_check`가 적어 둔 것과 견주는 값과 같다.

`pack_choices`는 변이를 하나씩 만들지 않는다(`theory.md` 7절). 센서 1,000개까지의 무선 센서 네트워크 묶음에서 변이 9,000개와 선택지 1,000개짜리 선택 지점을 바로 답한다. 선택의 핵만 보므로 결합과 속성의 검사는 `pack_check`가 한다. 펼친 나무의 노드를 가리킨 결정(node)은 다루지 않는다(A2).

## 4. 부호와 그다음에 할 일

| 부호 | 뜻 | 에이전트가 할 일 |
|---|---|---|
| A0 | 입력이 틀렸다. 모르는 항목, 없는 항목, 틀린 타입, 작업 자리 밖의 경로, 없는 사례 | 입력을 고쳐 다시 부른다. 묶음은 건드리지 않는다 |
| A1 | 그런 연산이 없다 | `ses ops`의 이름을 쓴다 |
| A2 | 이 연산이 하지 않는 일이다. 한도를 넘은 것 포함 | 줄이 적은 대로 입력이나 결정을 바꾼다 |
| A9 | 도구의 결함이다 | 고치려 하지 말고 사람에게 그 입력과 함께 알린다 |
| P0 | 선언(pack.yaml) | 선언을 고친다 |
| P1 | 문서 | 문서를 고친다. 줄이 어느 정의의 무엇인지 적는다 |
| P2 | 모델 베이스 | 모델의 코드를 고친다 |
| P3 | 바인딩 | 바인딩을 고친다 |
| P4 | 사례의 결정 | 결정 집합을 고친다. 모자라면 남은 선택지가 줄에 있다 |
| P5 | 조립과 실행 가능성 | 문서의 결합, 바인딩, 모델의 포트 가운데 줄이 가리키는 것을 고친다 |
| P6 | 실행과 기록 | 멈췄으면 모델을 고친다. 기록이 달라졌으면 뜻한 변화인지 먼저 판단한다 |
| P7 | 실행기 사이의 일치 | 모델이 계약을 어긴 곳을 찾는다(20 문서의 1절) |

P6의 "기록이 적어 둔 것과 다르다"는 판단이 필요한 줄이다. 모델이나 문서를 뜻대로 고친 결과이면 `record`를 켜고 `pack_check`를 다시 부른다. 뜻하지 않은 변화이면 기록을 다시 적지 말고 원인을 고친다. 검사를 통과시키려고 기록을 다시 적는 것은 검사를 끄는 것과 같다. 이것을 막는 장치는 없다. 누가 언제 기록을 다시 적었는지는 저장소의 이력으로 본다.

## 5. 쓰는 법

명령으로.

```bash
ses ops
```

```bash
ses call pack_new --args '{"dir": "mylab"}'
```

```bash
ses call pack_check --args '{"dir": "mylab"}'
```

`ses call`은 봉투를 표준 출력의 마지막 줄에 JSON 한 줄로 낸다. 종료 코드는 `ok`가 참이면 0, 거짓이면 1이다. 입력은 `--args`의 글이나 `--args-file`의 파일(`-`이면 표준 입력)로 준다. 작업 자리는 `--root`로 주고, 주지 않으면 지금 디렉터리다.

파이썬에서.

```python
from ses_core import ops

env = ops.call("pack_choices", {"dir": "mylab", "case": "slow"}, root="/work")
for f in env["findings"]:
    print(f["severity"], f["code"], f["where"], f["message"])
```

도구 정의로. `ses ops --tools`와 `ops.tools()`는 연산마다 `name`, `description`, `input_schema`를 가진 목록을 낸다. 도구를 부르는 에이전트 틀에 그대로 넣을 수 있게 이름은 영문자, 숫자, 밑줄만 쓰고, 입력 스키마는 기본 타입과 `additionalProperties: false`만 쓴다. 수의 범위 같은 조건은 스키마에 두지 않고 연산이 보고 A0로 알린다. 특정 회사의 API에 올려 시험하지는 않았다(7절의 R2).

에이전트가 도는 고리는 이렇다.

1. `pack_show`로 묶음을 읽는다. 처음이면 `pack_new`로 만든다.
2. 파일을 고친다.
3. `pack_check`를 부른다. error가 있으면 부호가 가리키는 파일을 고치고 3을 되풀이한다.
4. 구조를 봐야 하면 `pack_choices`와 `pack_build`를, 행동을 봐야 하면 `pack_run`을 부른다.
5. 뜻한 변화로 기록이 달라졌으면 `record`를 켜고 `pack_check`를 부른다.

## 6. 지키는지 보는 것

`tests/test_ops.py`가 61건으로 본다.

- 부른 결과가 모두 봉투의 스키마에 맞고 JSON으로 오간다.
- 연산마다 사람이 쓰는 명령이나 `pack.check`와 같은 답을 낸다. 지문, 변이의 수, 사건의 수.
- 틀린 입력 27가지가 A0나 A1의 줄이 되고 아무 파일도 바뀌지 않는다.
- 묶음의 선언, 문서, 모델 베이스, 바인딩, 결정을 하나씩 깨뜨린 15가지가 그 자리의 부호로 알려진다.
- 묶음의 코드가 글을 찍거나, 프로세스를 끝내려 하거나, JSON으로 옮길 수 없는 값을 내도 봉투가 온다.
- 읽기만 하는 연산의 앞과 뒤에 작업 자리의 모든 파일의 내용이 같다.
- 입력의 검사가 JSON Schema의 구현(jsonschema)과 무작위 입력 3,600개에서 같은 판정을 낸다.
- 이 문서의 표(연산의 이름, 입력, 부호, 한도)가 코드와 어긋나지 않는다.

변이 검사(`tools/mutants.py`)에 약속을 깨는 변이 12개(O1에서 O12)를 두었다.

## 7. 한계와 남은 것

| 번호 | 내용 |
|---|---|
| R1 | 평가가 없다. 에이전트가 이 연산들로 과제를 푸는지, 검사가 없을 때보다 나은지를 재지 않았다. 과제, 기준선, 기록의 형식을 정하는 것이 다음 일이다 |
| R2 | 실제 에이전트 틀에 올려 보지 않았다. 도구 정의의 모양은 흔한 형식을 따랐으나 어떤 API에도 보내 보지 않았다 |
| R3 | 묶음의 코드를 가두지 않는다(1절). 표준 출력은 파이썬 수준에서만 가로챈다. 파이썬 밖의 코드가 직접 찍는 글은 `ses call`의 출력 앞쪽에 섞일 수 있다. 봉투는 마지막 줄이다 |
| R4 | 시간 제한이 없다. 끝나지 않는 모델은 연산을 끝내지 않는다. 부르는 쪽이 제한을 건다 |
| R5 | 줄의 `message`는 한국어이고 사람이 읽는 글이다. 기계가 읽을 것은 `code`와 `where`다. 모자란 결정의 남은 선택지처럼 글 속에만 있는 정보가 있다 |
| R6 | 문서, 결정 집합, 바인딩의 형식을 알려 주는 연산이 없다. 에이전트는 `pack_new`가 만든 파일의 설명과 `schema/`의 스키마로 형식을 안다. 스키마는 저장소에 있고 설치된 꾸러미에는 들어 있지 않다. 틀린 열쇠는 적재기와 결정 집합의 읽기가 뜻했을 항목과 함께 알린다 |
| R9 | 연산을 에이전트에게 맡겨 본 적이 없다. 연구자의 역할을 맡긴 에이전트 여섯은 명령줄을 썼다(20 문서의 6절). 그 검증에서 나온 것(모델의 예외의 자리, 받은 값을 고친 모델, 결정이 모자랄 때의 알림)은 연산의 줄에도 그대로 나온다 |
| R7 | 묶음 밖의 문서 하나를 다루는 연산이 없다. 단위는 묶음이다. 구조만 가진 묶음(모델 베이스 없음)이 그 경우를 받는다 |
| R8 | 뜻에 대한 결정 둘이 열려 있다(ROADMAP의 정해야 할 것 1과 4). 정해지면 우선순위를 쓰는 문서와 자리를 가리킨 분해의 결정에 대한 `pack_choices`와 `pack_build`의 답이 달라진다. 판 1.0은 그 범위 밖에서만 굳었다 |
